# Бюро аномальных происшествий

Учебный проект для освоения современного Angular после React/Next.js.
Стек: Angular 22, TypeScript, Tailwind CSS, pnpm.

[Визуальный ориентир](docs/references/agency-initial-reference.png)

## Формат работы

Короткое объяснение → одна маленькая задача → самостоятельный код → проверка.
Новые концепции сравниваем с React/Next.js и сопровождаем точечными ссылками на angular.dev.
Ключевую логику пишет ученик; помощник объясняет, проверяет и помогает с рутиной.

- [x] **Корневой маршрут архива.** Разместить архив на `/`, без обязательного префикса `/archive`. Выделить `ArchivePage`, оставить общую шапку в App. Разобрать конфигурацию маршрутов, `RouterOutlet` и lazy loading.
- [x] **Выбранное дело в URL.** Добавить `/cases/:caseId`, сохранив список слева и подробности справа. Сделать URL источником выбранного ID. Освоить `Router.navigate`, `ActivatedRoute`, `paramMap`, `snapshot`, `toSignal` и `computed`; выбирать дело по прямой ссылке и при переходах назад/вперёд.
- [x] **Статус в URL.** Читать статус из `queryParamMap`, обновлять его через `Router.navigate` и сохранять остальные query-параметры через `merge`. Отсутствие параметра означает «Все статусы»; сброс удаляет параметр.
- [x] **Проверка статуса из URL.** Завести `CASE_STATUSES` и вывести тип через `(typeof CASE_STATUSES)[number]`. Проверять строку по массиву; для неизвестного значения использовать «Все статусы». Через `effect` удалять некорректный или пустой параметр из адреса, прекращая обработку, когда параметр отсутствует.
- [x] **Категория, угроза и регион в URL.** Читать выбранные значения из query-параметров и записывать их при выборе. Для угрозы преобразовывать строки в числа и различать отсутствие параметра («Любой») и `unrated` («Не оценён», внутри приложения — `null`). Допустимые регионы брать из данных дел. Поиск пока оставляем локальным состоянием компонента.
- [x] **Общий сброс и очистка параметров.** Сбрасывать четыре фильтра одной навигацией, сохраняя поиск. Проверять значения известных query-параметров в одном эффекте, собирать неправильные параметры в объект со значениями `null` и удалять их одним `navigate`. При пустом объекте не выполнять переход; сохранять корректные параметры и `unrated`.
- [x] **Скрывать подробности дела вне результатов.** Искать выбранный по URL объект в `filteredCases()`; возвращать `null`, если дело исключено поиском или фильтрами. Панель подробностей скрывается через `@if`. Окончательное снятие выбора через URL реализовано отдельно ниже.
- [x] **Сохранять query-фильтры при выборе дела.** Переход по карточке меняет ID дела и сохраняет параметры статуса, категории, угрозы и региона через `queryParamsHandling: 'merge'`. Локальный поиск остаётся состоянием компонента: его сброс при пересоздании страницы принят как допустимое поведение. Переносить поиск в URL или хранилище пока не требуется.
- [x] **Снимать выбор через URL, если дело исключено фильтрами.** Отдельный эффект проверяет наличие ID, существование дела среди всех `cases` и его отсутствие в `filteredCases()`. Переход на `/` убирает ID и сохраняет query-параметры через `merge`. При возврате прежнего региона дело появляется без автоматического выбора — проверено вручную. Пока дело остаётся в результатах, выбор сохраняется. Сброс локального поиска при пересоздании страницы допустим. Пояснение пользователю при снятии выбора из присланной ссылки пока не реализовано; к нему можно вернуться при разборе сообщений о состоянии URL.
- [x] **Разобрать структуру ArchivePage.** Проверки параметров URL и подготовка объекта для удаления некорректных значений вынесены в `archive-query-params.ts`. Общая навигация для изменения и сброса фильтров собрана в `updateQueryParams`. Отбор дел вынесен в обычную функцию `filterCases` в `archive-filtering.ts`; `computed` читает сигналы и передаёт значения функции. Эффекты зарегистрированы в конструкторе без ненужной ссылки `statusChange`. Сервис на этом этапе не требуется. Сохранение прежнего поведения проверено пользователем; согласованный рефакторинг завершён.
- [ ] **Неизвестное дело в URL.** Обработать `/cases/:caseId` с несуществующим ID: показать понятное сообщение и возможность вернуться в архив. Отдельно разобрать `RouterLink`.
- [ ] **Проверить историю навигации.** Проверить восстановление фильтров при перезагрузке и переходах назад/вперёд. Разобрать исправление некорректного URL без лишней записи в истории. Удаление неизвестных имён query-параметров пока отложено; текущая очистка проверяет только значения четырёх известных фильтров.
- [ ] **Формы.** Создавать и редактировать дело. Освоить актуальный API форм Angular и валидацию.
- [ ] **Данные и DI.** Вынести работу с делами в сервис, разобраться с `inject()`. Затем подключить простой API и БД: `HttpClient`, Observable, загрузка и ошибки.
- [ ] **Закрытый раздел.** Изучить функциональный guard и interceptor на учебном сценарии доступа. Guard управляет навигацией; защиту данных обеспечивает сервер.
- [ ] **Завершение.** Довести интерфейс до референса, проверить основные сценарии и развернуть приложение на VPS. Визуальная часть уже существенно продвинулась: оформлены шапка, фильтры, карточки и подробности дела; дальнейшая работа над оформлением ведётся отдельно.

## Границы

Сначала механики Angular, затем инфраструктура. Модель данных и компоненты уточняем по мере необходимости.
Без полноценной регистрации, сложных permissions, микросервисов и абстракций на будущее.
OOP, generics и RxJS разбираем там, где они помогают конкретной задаче.

## Готово, когда

Можно найти дело, открыть его, создать и отредактировать запись с сохранением данных.
Основные механики Angular понятны, приложение работает на VPS. На этом учебный проект завершён.
