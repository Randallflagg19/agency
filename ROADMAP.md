# Бюро аномальных происшествий

Учебный проект для освоения современного Angular после React/Next.js.
Стек: Angular 22, TypeScript, Tailwind CSS, pnpm.

[Визуальный ориентир](docs/references/agency-initial-reference.png)

## Формат работы

Короткое объяснение → одна маленькая задача → самостоятельный код → проверка.
Новые концепции сравниваем с React/Next.js и сопровождаем точечными ссылками на angular.dev.
Ключевую логику пишет ученик; помощник объясняет, проверяет и помогает с рутиной.

## Этапы

- [x] **Старт.** Создать проект, запустить его, разобрать scaffold и сохранить референс.
- [x] **Первая интерактивность.** Связать кнопку с методом класса, изменить signal и увидеть обновление шаблона.
- [x] **Закрепить основу.** Разобрать класс, декоратор, standalone, шаблон, события и signals на уже написанном коде.
- [x] **Чистая страница.** Убрать демонстрационную разметку, оставить минимальную оболочку и базовый визуальный фон приложения. Актуализировать стартовый тест.
- [x] **Первый дочерний компонент.** Создать статическую карточку дела и подключить её в App через импорт класса, `imports` и selector в шаблоне.
- [x] **Входные данные карточки.** Передать название и строковый номер из App через обязательные `input()`, прочитать их в шаблоне.
- [x] **Модель дела.** Согласовать поля дела и описать интерфейс и связанные типы в `case.model.ts`.
- [x] **Объект дела и события.** Передать типизированный объект в карточку. Освоить события через `output()` и хранение выбранного ID в signal родителя.
- [x] **Список дел.** Подключить массив учебных данных, вывести карточки через `@for` с `track` и использовать `@if` для условного отображения.
- [x] **Панель выбранного дела.** Получить выбранный объект через `computed` и показать его подробности справа от списка.
- [x] **Поиск по названию.** Связать поле ввода с signal, фильтровать список через `computed` без учёта регистра и крайних пробелов, показать пустой результат через `@empty`.
- [x] **Компонент подробностей — CaseDetails.** Вынести существующую панель и её стили в третий компонент с обязательным input дела. Сохранить выбор и вычисление выбранного дела в App, не меняя поведения.
- [x] **Панель поиска и фильтров — CaseFilters.** Создать четвёртый компонент и сначала перенести в него работающий поиск. Текущие значения передавать через inputs, изменения — через outputs; состояние и вычисление списка оставить в App. Убрать учебный вывод «Запрос: …».
- [x] **Основные фильтры архива.** Добавить статус, категорию, уровень угрозы 1–5 и регион из уникальных значений дел. Применять поиск и все активные фильтры совместно; предусмотреть варианты «Все»/«Любой». Общий сброс возвращает фильтры к исходным значениям, сохраняя поисковую строку.
- [x] **Неоценённая угроза.** Добавить вариант «Не оценён» для отбора дел с `threatLevel: null`, отличая его от «Любой».
- [x] **Первое оформление архива.** Оформить шапку бюро и панель поиска и фильтров по референсу. Сохранить связь элементов управления с состоянием App.
- [x] **Выбор дела при фильтрации.** Сохранять выбор, пока дело входит в результаты поиска и фильтров. Если оно исчезло из результатов, сбрасывать выбранный ID и закрывать подробности; при ослаблении фильтров не открывать его автоматически.
- [ ] **Корневой маршрут архива.** Разместить архив на `/`, без обязательного префикса `/archive`. Выделить компонент страницы, оставить общую шапку в App. Разобрать конфигурацию маршрутов, `RouterOutlet` и lazy loading.
- [ ] **Дело в URL.** Добавить `/cases/:caseId`, сохранив список слева и подробности справа. Сделать URL источником выбранного ID; освоить `RouterLink`, параметры пути, историю браузера и обработку неизвестного дела.
- [ ] **Фильтры в URL.** Сохранять поиск, статус, категорию, угрозу и регион в query-параметрах. Восстанавливать состояние при открытии ссылки, перезагрузке и переходах назад/вперёд. При снятии выбора убирать ID из пути, сохраняя фильтры. Если дело в присланной ссылке не соответствует фильтрам, снимать выбор с пояснением. Разобрать обновление адреса без записи каждой введённой буквы в историю.
- [ ] **Формы.** Создавать и редактировать дело. Освоить актуальный API форм Angular и валидацию.
- [ ] **Данные и DI.** Вынести работу с делами в сервис, разобраться с `inject()`. Затем подключить простой API и БД: `HttpClient`, Observable, загрузка и ошибки.
- [ ] **Закрытый раздел.** Изучить функциональный guard и interceptor на учебном сценарии доступа. Guard управляет навигацией; защиту данных обеспечивает сервер.
- [ ] **Завершение.** Приблизить интерфейс к референсу, проверить основные сценарии и развернуть приложение на VPS.

## Границы

Сначала механики Angular, затем инфраструктура. Модель данных и компоненты уточняем по мере необходимости.
Без полноценной регистрации, сложных permissions, микросервисов и абстракций на будущее.
OOP, generics и RxJS разбираем там, где они помогают конкретной задаче.

## Готово, когда

Можно найти дело, открыть его, создать и отредактировать запись с сохранением данных.
Основные механики Angular понятны, приложение работает на VPS. На этом учебный проект завершён.
