# Бюро аномальных происшествий

Учебный проект для освоения современного Angular после React/Next.js.
Стек: Angular 22, TypeScript, Tailwind CSS, pnpm.

[Визуальный ориентир](docs/references/agency-initial-reference.png)

## Формат работы

Короткое объяснение → одна маленькая задача → самостоятельный код → проверка.
Новые концепции сравниваем с React/Next.js и сопровождаем точечными ссылками на angular.dev.
Ключевую логику пишет ученик; помощник объясняет, проверяет и помогает с рутиной.

## Команда для локальной разработки

Для следующих занятий используем **`pnpm dev`** из корня проекта.
Она в одном терминале запускает SSH-туннель к `cutesnipe`, затем API и Angular.
API ждёт туннель, Angular — успешный ответ `GET /api/cases`.
Открывать `http://localhost:4200`; остановка всей связки — **Ctrl+C**.
Если один процесс завершается, остальные процессы этого запуска тоже останавливаются.

Один раз заполнить закрытый `server/.env`: API_PORT=3000, PGHOST=127.0.0.1,
PGPORT=15432, PGDATABASE=agency_db, PGUSER=agency_app и пароль PGPASSWORD.
Перед переходом на эту команду остановить ранее запущенные вручную Angular,
API и туннель через Ctrl+C в их терминалах, чтобы освободить порты.
Если SSH попросит пароль или парольную фразу ключа, ввести её в этом терминале.
Инструкция запуска и диагностики: [README.md](README.md#development-server).

- [x] **Скрывать подробности дела вне результатов.** Искать выбранный по URL объект в `filteredCases()`; возвращать `null`, если дело исключено поиском или фильтрами. Панель подробностей скрывается через `@if`. Окончательное снятие выбора через URL реализовано отдельно ниже.
- [x] **Сохранять query-фильтры при выборе дела.** Переход по карточке меняет ID дела и сохраняет параметры статуса, категории, угрозы и региона через `queryParamsHandling: 'merge'`. Локальный поиск остаётся состоянием компонента и сохраняется при выборе дела: `/` и `/cases/:caseId` теперь используют одну запись маршрута с `matcher`, поэтому ArchivePage не пересоздаётся. Переносить поиск в URL или хранилище пока не требуется.
- [x] **Снимать выбор через URL, если дело исключено фильтрами.** Отдельный эффект проверяет наличие ID, существование дела среди всех `cases` и его отсутствие в `filteredCases()`. Переход на `/` убирает ID и сохраняет query-параметры через `merge`. При возврате прежнего региона дело появляется без автоматического выбора — проверено вручную. Пока дело остаётся в результатах, выбор сохраняется. Переход на `/` теперь сохраняет экземпляр ArchivePage, локальный поиск и загруженные дела. Пояснение пользователю при снятии выбора из присланной ссылки пока не реализовано; к нему можно вернуться при разборе сообщений о состоянии URL.
- [x] **Разобрать структуру ArchivePage.** Проверки параметров URL и подготовка объекта для удаления некорректных значений вынесены в `archive-query-params.ts`. Отбор дел вынесен в обычную функцию `filterCases` в `archive-filtering.ts`; `computed` читает сигналы и передаёт значения функции. Эффекты зарегистрированы в конструкторе без ненужной ссылки `statusChange`. Сервис на этом этапе не требуется. Сохранение прежнего поведения проверено пользователем; согласованный рефакторинг завершён.
- [x] **Неизвестное дело в URL.** `isCaseNotFound` проверяет наличие ID и отсутствие дела среди всех `cases`. - [x] **Проверить историю навигации.** Пользователь проверил переходы назад/вперёд, восстановление query-фильтров (включая «Не оценён») и выбранного дела после перезагрузки: всё работает. Полировка автоматических исправлений через `replaceUrl` пока отложена и не реализована, как и удаление неизвестных имён query-параметров; текущая очистка проверяет только значения четырёх известных фильтров.

- [ ] **Данные и DI — разобрать готовую реализацию.** По просьбе пользователя помощник добавил `CasesApi` с `HttpClient`, `inject()` и загрузкой из `GET /api/cases` вместо моков. ## Следующий старт: форма создания дела

Начать с небольшого рабочего фрагмента, затем расширять его. Реализацию пользователь пишет самостоятельно; помощь — постановка задачи, постепенные подсказки и проверка результата.

1. Создать страницу создания дела и маршрут `/cases/new`. Поставить этот маршрут перед маршрутом архива с `matcher`, чтобы `new` не воспринимался как ID. Архив использует одну запись маршрута для `/` и `/cases/:caseId`: выбор и закрытие дела не пересоздают страницу и не повторяют GET. Связать кнопку «Новое дело» с этой страницей через `RouterLink`.
2. Первый учебный шаг — только поле названия: отдельная модель черновика в `signal`, создание формы через `form`, привязка поля через `FormField`, обязательность через `required`. Разобраться, где значение поля, где состояние ошибки и когда показывать сообщение. Использовать связанный `label` и понятный текст ошибки.
3. Добавить описание и основные поля: статус, категорию, уровень угрозы и местоположение. Сначала согласовать начальные значения и обязательность. Черновик формы не обязан совпадать с `IncidentCase`: ID, уникальный номер и дату регистрации не заставлять пользователя заполнять ради соответствия модели. Загрузку изображения и дополнительные поля не включать в первый шаг.
4. Реализовать отправку и отмену. Первый результат — получение типизированного черновика при допустимом вводе без записи в БД и без сообщения об успешном сохранении. Затем подключить сервис/API и отображение результата или ошибки сохранения. После подключения API не допускать повторной отправки во время запроса.
5. После создания разобрать редактирование: заполнение формы существующими данными, сохранение изменений и отмена без изменения исходного дела.

Критерий первого занятия: страница открывается по кнопке, название связано с моделью, пустое название не принимается, ошибка понятна, отмена возвращает в архив. Для этого БД пока не нужна.

Документация: [Signal Forms — обзор](https://angular.dev/guide/forms/signals/overview).

## Границы

Сначала механики Angular, затем инфраструктура. Модель данных и компоненты уточняем по мере необходимости.
Без полноценной регистрации, сложных permissions, микросервисов и абстракций на будущее.
OOP, generics и RxJS разбираем там, где они помогают конкретной задаче.
