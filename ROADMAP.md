# Бюро аномальных происшествий

Учебный проект для освоения современного Angular после React/Next.js.
Стек: Angular 22, TypeScript, Tailwind CSS, pnpm.

[Визуальный ориентир](docs/references/agency-initial-reference.png)

## Формат работы

Короткое объяснение → одна маленькая задача → самостоятельный код → проверка.
Новые концепции сравниваем с React/Next.js и сопровождаем точечными ссылками на angular.dev.
Ключевую логику пишет ученик; помощник объясняет, проверяет и помогает с рутиной.

## Команда для локальной разработки

Для следующих занятий используем **`pnpm dev`** из корня проекта.
Она в одном терминале запускает SSH-туннель к `cutesnipe`, затем API и Angular.
API ждёт туннель, Angular — успешный ответ `GET /api/cases`.
Открывать `http://localhost:4200`; остановка всей связки — **Ctrl+C**.
Если один процесс завершается, остальные процессы этого запуска тоже останавливаются.

Один раз заполнить закрытый `server/.env`: API_PORT=3000, PGHOST=127.0.0.1,
PGPORT=15432, PGDATABASE=agency_db, PGUSER=agency_app и пароль PGPASSWORD.
Перед переходом на эту команду остановить ранее запущенные вручную Angular,
API и туннель через Ctrl+C в их терминалах, чтобы освободить порты.
Если SSH попросит пароль или парольную фразу ключа, ввести её в этом терминале.
Инструкция запуска и диагностики: [README.md](README.md#development-server).

## Продолжение: форма создания дела

Начать с небольшого рабочего фрагмента, затем расширять его. Реализацию пользователь пишет самостоятельно; помощь — постановка задачи, постепенные подсказки и проверка результата.

Первичное знакомство завершено: страница, два обязательных поля, сообщения ошибок и отправка в консоль уже реализованы. Чтение данных из PostgreSQL через API также разобрано.

Состав и поведение согласованы:

| Поле черновика | Начальное значение | Ввод и ограничения |
| --- | --- | --- |
| `title` | `''` | Обязательный input, до 150 символов |
| `description` | `''` | Обязательный textarea, до 10 000 символов |
| `category` | `'unknown'` | Select из допустимых категорий; «Не определена» по умолчанию |
| `threatLevel` | `null` | Select: «Не оценён» или число 1–5 |
| `region` | `''` | Необязательная строка до 150 символов; подсказки из имеющихся регионов с возможностью ввести новый |
| `locationDescription` | `''` | Необязательный textarea, до 1 000 символов |
| `address` | `''` | Необязательная строка до 300 символов |

Обязательные строки не могут состоять только из пробелов. Ограничения проверяются в форме и на сервере. В текущей схеме БД ограничения длины ещё не заданы.

При отправке пустое местоположение становится `location: null`. Если заполнено хотя бы одно поле места, формируется объект `location`: пустые регион и адрес становятся `null`, описание места может быть пустой строкой. Сервер назначает ID, уникальный номер, дату регистрации и статус `'new'`. Ответственный и заключение первоначально `null`, теги и связанные дела — пустые массивы. Выбор статуса будет в редактировании.

Фотография обязательна для новых дел: JPEG/PNG/WebP до 5 МиБ и 25 мегапикселей, без анимации. Старые записи без фото остаются допустимыми. Файл хранится отдельно от текстового черновика в `selectedPhoto`; при отправке оба попадают в FormData.

«Создать дело» проверяет форму и отправляет данные. При ошибке введённые значения сохраняются, при успехе открывается созданное дело. Во время запроса повторная отправка и отмена недоступны.

«Отмена» возвращает на `/` без создания записи. Если значения отличаются от начальных, показать подтверждение «Отменить создание? Введённые данные будут потеряны». Без изменений — сразу вернуться в архив. Отдельная кнопка очистки не нужна. Подтверждение других способов ухода со страницы пока отложено.

1. Прочитать изменения в CasesApi и серверном обработчике: FormData → проверка → Cloudinary → INSERT → открытие дела.
2. Перезапустить `pnpm dev`, войти и создать дело с фото. Проверить файл в папке `agency` и отображение после обновления страницы.
3. Затем разобрать редактирование: заполнение формы существующими данными, сохранение изменений и отмена без изменения исходного дела. Удаление и полировка дизайна остаются отдельными задачами.

Документация: [Signal Forms — обзор](https://angular.dev/guide/forms/signals/overview).
