# Общее правило для всех пунктов

Этот документ описывает только визуальную реализацию референса.

НЕ нужно самостоятельно проектировать или писать функциональность приложения.

Не создавать без отдельного запроса:

- Angular services;
- routes;
- guards;
- формы;
- API;
- бизнес-логику;
- состояние приложения;
- mock/seed data;
- обработчики пользовательских действий;
- поиск и фильтрацию;
- архитектуру приложения.

Не менять существующую логику приложения ради визуальной задачи.

Если для демонстрации визуального элемента нужен HTML, используй минимальную существующую разметку или предложи минимальный placeholder, но не развивай его в функциональность.

Главная задача этого документа:

- CSS;
- визуальные ассеты;
- SVG;
- размеры;
- цвета;
- типографика;
- текстуры;
- расположение декоративных элементов;
- визуальное соответствие референсу.

Логику и Angular-функциональность я буду реализовывать отдельно сам в учебном режиме.

1. # Background task

Нужно реализовать только общий фон приложения по визуальному референсу.

## Цель

Фон должен напоминать старую архивную бумагу:

- тёплый светло-бежевый основной цвет;
- очень слабая неоднородность;
- едва заметные пятна и потёртости;
- лёгкое ощущение старого документа;
- без сильного grunge;
- без хоррора;
- без крупных контрастных пятен;
- текст поверх фона должен оставаться легко читаемым.

По ощущению нужно приблизиться к бумажной основе из приложенного референса примерно на 70–80%, но пока без использования изображений.

## Ограничения

Пока НЕ нужно делать:

- sidebar;
- header;
- карточки дел;
- фильтры;
- поиск;
- фотографии;
- штампы;
- любую функциональность приложения.

Работаем только с общим фоном.

## Реализация

Сначала попробуй реализовать фон только средствами CSS.

Можно использовать:

- базовый `background-color`;
- несколько мягких `radial-gradient`;
- слабые `linear-gradient`;
- `repeating-linear-gradient`, если это действительно помогает;
- pseudo-element для очень слабого grain/noise, если он не мешает интерфейсу.

Фон должен:

- нормально работать на страницах любой высоты;
- не зависеть от конкретного размера экрана;
- быть глобальной основой приложения;
- не привлекать к себе слишком много внимания.

## Перед изменениями

Сначала коротко объясни:

1. Из каких CSS-слоёв ты собираешь фон.
2. Что делает каждый слой.
3. Почему пока не нужна отдельная PNG/JPG-текстура.

После этого внеси минимальные изменения только для реализации фона.

Не переходи к следующим частям интерфейса.

## После выполнения

Покажи:

- какие файлы были изменены;
- где именно теперь задаётся фон;
- какие параметры проще всего менять, если я захочу сделать бумагу светлее, темнее, грязнее или чище.

Если по результату CSS окажется слишком стерильным, следующим отдельным шагом мы добавим небольшую бесшовную текстуру бумаги.

> Sidebar task отложен до появления реальной навигации.
> Пока не создавать декоративный sidebar и не добавлять неработающие пункты меню.

2. # Sidebar background task

Нужно реализовать только визуальную основу левого sidebar по референсу.

## Сейчас сделать

- если основной layout и sidebar уже существуют — не менять их архитектуру, только стилизовать;
- если sidebar ещё отсутствует — сначала покажи минимальное визуальное изменение, необходимое для его отображения, и дождись подтверждения перед созданием новой структуры.
- sidebar должен занимать примерно 220–240 px на desktop;
- высота — минимум весь viewport;
- фон sidebar — очень тёмный графитово-оливковый, а не чисто чёрный;
- добавить очень слабую неоднородность через CSS gradients;
- сделать тонкое визуальное разделение между sidebar и основной областью;
- сохранить уже существующий бумажный фон основной области.

## Пока НЕ делать

- пункты меню;
- иконки;
- active states;
- текст;
- логотип;
- штампы;
- фотографию здания до завершения базовой стилизации sidebar;
- responsive/mobile menu.

## Визуальное направление

Sidebar должен ощущаться как тёмная панель старой ведомственной архивной системы, а не как современный SaaS dashboard.

Не использовать сильный grunge, яркие gradients или абсолютный чёрный цвет.

## Перед изменениями

Сначала объясни:

1. какую структуру layout предлагаешь;
2. какой способ используешь — grid или flex — и почему;
3. из каких CSS-слоёв будет состоять фон sidebar.

После этого реализуй только этот слой.

## Изображение здания

Для нижней части sidebar уже подготовлен визуальный референс:

`docs/references/sidebar-agency-building.png`

Пока воспринимай его как исходный визуальный ассет.

После создания базового sidebar:

- предложи рабочее место для изображения в runtime assets;
- используй его в нижней части sidebar;
- изображение должно быть сильно приглушено;
- оно не должно конкурировать с навигацией;
- можно использовать `opacity`, gradient mask и `filter`;
- верхняя часть изображения должна плавно растворяться в фоне sidebar.

Не добавляй текст непосредственно в изображение.
Надписи, штампы и служебную информацию будем делать HTML/CSS.

## 3. Эмблема Бюро

Нужно подготовить и подключить эмблему организации по приложенному визуальному референсу.

Референс:

`docs/references/bureau-emblem-reference.png`

## Цель

Эмблема должна использоваться как официальный знак «Бюро аномальных происшествий».

Она должна ощущаться как:

- ведомственная;
- архивная;
- строгая;
- немного советская / постсоветская по характеру;
- связанная с аномальными явлениями;
- без ощущения современного стартап-логотипа.

## Что нужно сделать

1. Использовать PNG только как визуальный референс.
2. Сделать рабочую SVG-версию эмблемы для интерфейса.
3. SVG должна хорошо масштабироваться и оставаться читаемой при небольшом размере.
4. По возможности использовать:
   - простые `path`;
   - `circle`;
   - `line`;
   - другие обычные SVG-примитивы.
5. Не встраивать bitmap внутрь SVG.
6. Не делать SVG чрезмерно сложной.

## Визуально важно сохранить

- круговую форму;
- центральный щит / знак;
- символ глаза / наблюдения;
- геометрические орбиты / точки;
- декоративные ветви;
- строгую симметрию;
- тёмный монохромный стиль.

Не обязательно повторять референс пиксель в пиксель.

Главное — сохранить характер и узнаваемость.

## Цвет

Сделать SVG через `currentColor`, чтобы цвет можно было менять из CSS.

Например:

- тёмный графит;
- чёрный;
- тёмный оливковый;
- приглушённый архивный цвет.

## Размещение

Пока добавить только минимальное место для эмблемы в верхней части приложения.

Не делать полноценный header.

Не добавлять пока:

- большой заголовок;
- пользовательское меню;
- штамп «СЕКРЕТНО»;
- слоган;
- дополнительные элементы header.

Сейчас задача — только корректно подготовить и показать эмблему.

## Перед изменениями

Сначала коротко объясни:

1. Где будет храниться SVG.
2. Как ты собираешься подключить её в Angular.
3. Почему `currentColor` здесь удобнее жёстко заданного цвета.

После этого внеси минимальные изменения.

## После выполнения

Покажи:

- созданный SVG-файл;
- где он используется;
- какие CSS-параметры управляют:
  - размером;
  - цветом;
  - прозрачностью.

- thumbnail в списке дел;

Если соответствующая разметка списка дел уже существует — применить стили к ней.

Если её ещё нет — не создавать самостоятельно список дел и не придумывать данные.

Главная задача этого этапа:

## Перед изменениями

Сначала коротко объясни:

1. где лучше хранить рабочие изображения;
2. какие CSS-стили нужны для thumbnail;
3. как изображения будут обрезаться через `object-fit`;
4. какие существующие файлы потребуется изменить.

После этого внеси только визуальные изменения.

## После выполнения

Покажи:

- где лежат рабочие изображения;
- какие CSS-классы отвечают за thumbnail;
- какие параметры отвечают за размер, crop и визуальное оформление.

## 5. Большая фотография выбранного дела

Для детальной карточки выбранного дела не нужно создавать отдельное новое изображение.

Если соответствующее дело и поле изображения уже существуют в приложении,
используй тот же файл изображения, что и для thumbnail.

Не создавай для этого новую модель данных или дополнительное состояние.

Например:

`case-0147-elevator.png`

в списке дел используется как небольшой thumbnail, а в правой части выбранного дела — как крупное изображение.

## Цель

Показать, что одно и то же изображение может использоваться в разных контекстах интерфейса:

- маленький thumbnail в списке;
- крупное изображение в карточке выбранного дела.

Не нужно дублировать файл или создавать отдельную версию изображения.

## Что нужно сделать

1. Переиспользовать поле `image` из объекта дела.
2. В списке отображать изображение в компактном размере.
3. В детальной области выбранного дела показывать ту же фотографию крупнее.
4. Использовать CSS для:
   - разных размеров;
   - crop;
   - `object-fit`;
   - рамки;
   - лёгкого архивного оформления.

## Визуальное направление

Большая фотография должна выглядеть не как обычная картинка из современной карточки, а как архивный материал / приложенная к делу фотография.

Можно использовать:

- тонкую светлую рамку;
- лёгкую тень;
- небольшой поворот на 1–2 градуса;
- эффект вложенной фотографии;
- слабую бумажную окантовку;
- декоративную скрепку или уголок позже.

Важно не переусердствовать.

## Пока НЕ делать

- отдельную галерею;
- просмотр на весь экран;
- zoom;
- carousel;
- несколько фотографий на одно дело;
- загрузку файлов;
- отдельные thumbnails;
- отдельные image variants.

## Перед изменениями

Сначала объясни:

1. как одно поле `image` будет использоваться и в списке, и в детальной карточке;
2. как `object-fit` и размеры позволяют использовать один файл в двух разных визуальных ролях;
3. какие CSS-стили ты предлагаешь для ощущения архивной фотографии.

После этого внеси только минимальные изменения для крупного изображения выбранного дела.

## После выполнения

Покажи:

- где используется одно и то же поле `image`;
- какие CSS-классы отвечают за thumbnail;
- какие CSS-классы отвечают за большую фотографию;
- какие параметры проще всего менять для crop, размера и рамки.

## 6. Архивные штампы

Нужно реализовать декоративные архивные штампы по визуальному референсу.

Примеры:

- `СЕКРЕТНО`
- `ДЛЯ СЛУЖЕБНОГО ПОЛЬЗОВАНИЯ`
- при необходимости позже можно добавить `АРХИВ`, `НА КОНТРОЛЕ` и другие.

## Цель

Штампы должны выглядеть как старые ведомственные отметки на бумажных документах.

Они должны добавлять атмосферу, но не мешать чтению интерфейса.

## Важно

Не использовать PNG/JPG для штампов.

Сделать их обычным HTML-текстом и CSS.

Это позволит:

- сохранять чёткость на любом размере;
- менять текст без новых ассетов;
- легко регулировать цвет, наклон и прозрачность;
- переиспользовать один стиль для разных штампов.

## Визуальный стиль

Основной вариант:

- приглушённый тёмно-красный цвет;
- uppercase;
- заметный letter-spacing;
- рамка вокруг текста;
- небольшой `transform: rotate(...)`;
- лёгкая прозрачность;
- слегка неровное/потёртое ощущение без тяжёлых эффектов.

Штамп должен выглядеть как отпечаток чернил, а не как современная badge/pill UI.

## Реализация

Предпочтительно сделать штамп обычным HTML + CSS.
Не создавать отдельный Angular component/directive только ради декоративного штампа, если такой абстракции ещё нет в приложении.

Примерное использование:

```html
<span class="archive-stamp archive-stamp--secret"> СЕКРЕТНО </span>
```

## 7. Служебные иконки и декоративные элементы

Нужно подготовить визуальную систему небольших служебных иконок для интерфейса.

Для этого НЕ нужно генерировать отдельные изображения.

Использовать SVG и, где возможно, обычный CSS.

## Какие иконки понадобятся

Примерный набор:

- архив / папка;
- новое дело;
- замок / закрытый раздел;
- сотрудник / пользователь;
- поиск;
- фильтр;
- геолокация;
- календарь;
- документ / файл;
- изображение;
- аудиофайл;
- скачать;
- добавить;
- меню `...`;
- стрелка / раскрытие;
- возможно скрепка.

Не обязательно реализовывать весь список прямо сейчас.

Добавлять иконки только по мере появления соответствующих элементов интерфейса.

## Цель

Иконки должны поддерживать атмосферу архивной ведомственной системы, но не выглядеть как отдельные иллюстрации.

Они должны быть:

- простыми;
- небольшими;
- монохромными;
- хорошо читаемыми;
- визуально одинаковыми по стилю;
- не слишком современными и "глянцевыми".

## Формат

Предпочтительно использовать SVG.

Преимущества:

- хорошо масштабируется;
- легко менять цвет через CSS;
- остаётся резким;
- не требует отдельных PNG для каждого размера.

Желательно использовать `currentColor`, чтобы цвет наследовался от текста или CSS-класса.

## Библиотека или свои SVG

Сначала оцени, нужен ли вообще внешний icon package.

Если для текущего экрана достаточно нескольких простых иконок, предпочти небольшой собственный набор SVG.

Не устанавливай новую библиотеку без объяснения.

Если считаешь, что одна небольшая библиотека действительно лучше, сначала объясни:

1. какую предлагаешь;
2. зачем она нужна;
3. сколько реально будет использоваться;
4. почему это лучше нескольких локальных SVG.

Без моего подтверждения новую dependency не добавлять.

## Декоративная скрепка

Для фотографии дела или заметки позже может понадобиться скрепка.

Её тоже не нужно генерировать как отдельное изображение.

Можно использовать:

- простой SVG;
- CSS;
- небольшой декоративный элемент поверх фотографии.

Она должна быть очень ненавязчивой.

## Цвета

Иконки должны наследовать общий стиль интерфейса.

Возможные цвета:

- тёмный графит;
- приглушённый оливковый;
- светлый серо-бежевый для sidebar;
- тёмно-красный только для отдельных предупреждений.

Не использовать разноцветные icon sets.

## Пока НЕ делать

- animated icons;
- сложные hover-анимации;
- 3D;
- emoji вместо иконок;
- отдельные PNG;
- большое количество декоративных SVG;
- новую icon library без необходимости.

## Перед изменениями

Сначала коротко объясни:

1. какие иконки реально нужны на текущем этапе;
2. будешь ли использовать локальные SVG или библиотеку;
3. где они будут храниться;
4. как будет работать `currentColor`.

После этого реализуй только минимальный набор, который уже нужен существующему интерфейсу.

## После выполнения

Покажи:

- какие иконки добавлены;
- где они находятся;
- как меняются их размер и цвет;
- как добавить следующую иконку в том же стиле.

## 8. Архивная оболочка интерфейса

Нужно собрать общий визуальный язык карточек, панелей и документов так, чтобы приложение выглядело как старая ведомственная архивная система.

Отдельные новые изображения для этого пока не нужны.

Основу сделать средствами CSS.

## Цель

Интерфейс должен ощущаться как смесь:

- старой архивной карточки;
- бумажного дела;
- ведомственного формуляра;
- папки с вкладками;
- машинописного документа;
- строгой служебной системы.

При этом интерфейс должен оставаться современным и удобным для чтения.

## Основные визуальные элементы

Нужно подготовить базовые стили для:

- карточек дел;
- детальной панели выбранного дела;
- бумажных блоков;
- секций;
- вкладок;
- таблиц / строк metadata;
- разделительных линий;
- рамок;
- маленьких служебных подписей.

## Бумажные карточки

Карточки не должны выглядеть как современные SaaS cards с большими скруглениями.

Предпочтительно:

- почти прямые углы;
- очень небольшой `border-radius` или вообще без него;
- тонкие серо-коричневые рамки;
- тёплый бумажный фон;
- слабая внутренняя тень;
- очень лёгкая внешняя тень;
- небольшая разница оттенков между основной страницей и карточкой.

## Линии и разделители

Использовать:

- тонкие горизонтальные линии;
- dotted / dashed линии там, где это уместно;
- двойные линии в отдельных ведомственных блоках;
- небольшие подписи над секциями.

Не использовать тяжёлые толстые бордеры.

## Вкладки

Tabs должны напоминать вкладки бумажной папки или архивного дела.

Например:

- `Общее`;
- `Материалы`;
- `Хронология`;
- `Заключения`.

Активная вкладка может выглядеть как бумажный ярлык, слегка выступающий над основной карточкой.

Не делать их похожими на современные pill buttons.

## Края бумаги

Можно использовать CSS:

- pseudo-elements;
- небольшие тени;
- слабые gradients;
- лёгкий `box-shadow`;
- очень осторожный `transform`;
- небольшую разницу цвета по краям.

Не использовать тяжёлый torn-paper effect.

Никаких рваных PNG-масок пока не нужно.

Не создавать самостоятельно карточки, вкладки или структуру страницы только ради применения этих стилей.

Подготовить переиспользуемый визуальный слой и применять его к уже существующей разметке.

## Типографика

Нужно предусмотреть визуальную иерархию:

- крупный заголовок дела;
- регистрационный номер;
- маленькие служебные подписи;
- metadata;
- обычный текст описания.

Позже можно отдельно подобрать шрифты, но уже сейчас структура должна поддерживать ощущение документа.

## Важно

Не нужно превращать весь интерфейс в декоративный плакат.

Главное:

- читаемость;
- порядок;
- строгая сетка;
- аккуратные отступы;
- архивная атмосфера через детали.

## Пока НЕ делать

- полноценную адаптивную мобильную версию;
- сложные анимации;
- сильные текстуры;
- torn paper PNG;
- сложные маски;
- 3D;
- параллакс;
- декоративные эффекты ради эффектов.

## Перед изменениями

Сначала коротко объясни:

1. какие базовые CSS-классы ты предлагаешь создать;
2. как будешь визуально отличать:
   - общий фон страницы;
   - карточку дела;
   - детальную панель;
   - вкладки;
3. какие CSS-параметры будут отвечать за "бумажность";
4. какие эффекты сознательно НЕ будешь использовать, чтобы интерфейс не выглядел перегруженным.

После этого внеси только минимальные изменения.

## После выполнения

Покажи:

- какие базовые классы появились;
- где задаётся бумажный фон карточек;
- как меняются:
  - цвет бумаги;
  - рамки;
  - тени;
  - плотность разделительных линий;
- какие стили потом можно переиспользовать для новых страниц.
